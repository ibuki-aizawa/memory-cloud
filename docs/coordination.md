# 複数の AI での分担（協調）

Claude Code と Codex など、別々の AI が同じプロジェクトで並行して作業するためのしくみです。
**タスクボード**で作業を取り合わずに分担し、**受信箱**で引き継ぎやレビュー依頼を伝えます。

前提として、AI ツールごとに別のトークンを使っている必要があります（[エージェントの識別](agents.md)）。
同じトークンを共有していると、サーバーからは同じ AI に見えるため、分担できません。

## 流れの例

1. あなたが Claude Code に「ログイン画面を作って」と頼む
2. Claude Code はタスクを作って引き受け（`task_create` に `claim: true`）、自分のブランチで作業する
3. 終わったら Codex にレビューを頼む（`task_handoff` に `status: "review"`）。Codex の受信箱に知らせが届く
4. Codex は作業の始めに受信箱を見て（`read_inbox`）、レビューして完了にする（`task_update` に `status: "done"`）

AI どうしが直接話すのではなく、サーバーに置いた掲示板と郵便受けを、それぞれが見に行く形です。
相手がいま動いていなければ、次に動いたとき（作業の始めや、タスクの合間）に読まれます。

## タスク

タスクはプロジェクト（`memory-project`）ごとにあります。`memory-global` にもタスクを置けますが、ふつうはプロジェクトの側を使います。

| 状態 | 意味 |
|---|---|
| `open` | 未着手（誰も担当していない） |
| `in_progress` | 担当者が作業中 |
| `review` | レビュー待ち・レビュー中 |
| `done` | 完了 |
| `cancelled` | 取りやめ |

### 担当と期限

- `task_claim` で引き受けると、自分が担当になります。ほかの AI が担当しているタスクは引き受けられません
  （同時に引き受けようとしても、成功するのは 1 人だけです）
- 担当には **30 分の期限** があり、`task_update` を呼ぶたびに延びます。
  AI が途中で止まっても、期限が切れればほかの AI が引き受け直せます
- `task_handoff` で渡された側の期限は 24 時間です
- `status` を変えられるのは担当者だけです（管理者トークンは例外）。`note`（メモ）は誰でも書けます
- `status: "open"` にすると、担当を外して手放します

### 経過

作成・引き受け・メモ・引き継ぎは経過として残り、`task_get` で読めます。引き継いだ AI は、ここで前の担当者がやったことを確認できます。
一覧（`task_list`）は利用量を抑えるため、説明文を含みません。

## 受信箱

- `send_message` でほかの AI にメッセージを送り、`read_inbox` で自分宛てを読みます（読むと既読になります）
- 受信箱もプロジェクトごとです（`memory-global` で送ったものは `memory-global` で読みます）
- 宛先には、発行済みのエージェント名、`owner`（管理者トークン）、`github:<ユーザー名>/<アプリ名>`（OAuth。例 `github:alice/chatgpt`）が使えます。
  打ち間違いで届かないのを防ぐため、登録されていない名前には送れません
- `whoami` を呼ぶと、未読の数と自分が担当中のタスクの数もわかります

## ツール

| ツール | 用途 |
|---|---|
| `task_create` | タスクを作る（`claim: true` で同時に引き受ける） |
| `task_list` | 一覧（既定は終わっていないもの。`mine: true` で自分の担当だけ） |
| `task_get` | 詳細と経過 |
| `task_claim` | 引き受ける |
| `task_update` | 状態の変更・進捗メモ（担当の期限も延びる） |
| `task_handoff` | ほかの AI に渡す（相手の受信箱に知らせる） |
| `send_message` | メッセージを送る |
| `read_inbox` | 自分宛てのメッセージを読む |

## AI に渡すルール

`memory-kit/AGENTS.md` の「協調プロトコル」に書いてあります（導入すると各 AI ツールが読みます）。要点は次のとおりです。

- 作業の始めに `whoami` と `read_inbox`、`task_list` を確認する
- 作業する前に `task_claim` で引き受ける。担当中のタスクには手を出さない
- 自分のブランチ（または git worktree）で作業し、ほかの AI と同じファイルを同時に書き換えない
- 長い作業の途中では `task_update` でメモを残す（期限も延びる）
- 終わったら `done` にするか、`task_handoff` でレビューを頼む

## 注意

- サーバーから AI に知らせを押し出すしくみはありません。AI が受信箱を見に行ったときに読まれます
- タスクの担当は「取り合いを防ぐための約束」で、ファイルの書き込みそのものを止めるものではありません。
  ブランチを分けるルールと組み合わせて使ってください
